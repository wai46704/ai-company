# AdSense審査前点検レポート

- 点検日: 2026-08-11
- 点検者: リク（SEO分析担当）
- 対象: https://naoki-blog.com（Astro製、GitHub Pagesホスティング）
- 結論: **公開OK（軽微な要対応あり）**

Google AdSense公式ヘルプおよび複数の解説記事（2026-08-11時点でWeb検索により確認、出典は本文末尾）によると、2026年時点で重視されるのは主に「①独自コンテンツの充実」「②プライバシーポリシーの設置」「③モバイル対応」の3点。今回の点検では、この3点を含め、審査に大きく響く「致命的な不備」は見つかりませんでした。ただし、記事間で免責表現の有無にばらつきがある点など、YMYL（お金・健康など人生に影響する情報）ジャンルのサイトとして整えておいた方がよい点がいくつかあります。

## 【総合判定】公開OK

必須ページ・ads.txt・コンテンツ量・技術面はいずれも問題なし。下記「要対応」は審査落ちの直接原因になる可能性は低いですが、YMYL（お金）サイトとしての信頼性を高める観点で、余裕があれば申請前に直しておくことを推奨します。

## 1. 必須ページの有無 → 問題なし

| 項目 | 状況 |
|---|---|
| プライバシーポリシー | `src/pages/privacy.astro` あり。Cookie・アクセス解析・広告配信・アフィリエイト・免責事項・著作権まで網羅済み |
| 運営者情報・About | `src/pages/about.astro` あり。経歴・専門性（FP・簿記・行政書士学習）・発信方針・「金融商品の勧誘ではない」旨の断り書きも明記済み |

| 全ページからの導線 | ヘッダーに About / Blog / Contact、フッターにプライバシーポリシーへのリンクあり。全ページ共通で機能している |

### 特定商取引法に基づく表記について
Web検索で確認したところ（2026-08-11時点の複数の解説記事）、**自社で商品・サービスを直接販売せず、アフィリエイト（他社商品の紹介）と広告収入のみのブログには、特定商取引法に基づく表記は不要**というのが一般的な見解です。当サイトも独自商品の販売はなく、アフィリエイトリンクの存在はプライバシーポリシーに明記済みのため、追加対応は不要と判断します。
※ただし法律の最終的な該非判断は専門家でないと断定できません。将来、自分の商品・教材・コンサル等を直接販売する形に変わった場合は、そのタイミングで表記が必要になる点だけ留意してください。

## 2. ads.txt → 問題なし

- `public/ads.txt` は存在し、内容は以下の1行のみ：
  ```
  google.com, pub-1722999895287881, DIRECT, f08c47fec0942fa0
  ```
- `src/layouts/BaseLayout.astro` に記載の広告タグのパブリッシャーID `ca-pub-1722999895287881` と、`pub-1722999895287881` の部分が一致しており、対応関係は正しいです。
- ads.txtがない場合でも審査に即落ちるわけではありませんが、放置すると審査後の広告配信で警告が出ることがあるため、「最初から用意済み」なのは望ましい状態です。

## 4. 技術的な健全性 → 問題なし（1点だけ運用上の確認事項あり）

- **内部リンク切れ**: `src/content/blog/` 内の全記事内リンク（`/blog/xxx/` 形式、約100箇所）と、実在する23本のスラッグを突き合わせましたが、リンク切れは見つかりませんでした。
- **旧記事の統廃合リダイレクト**: `astro.config.mjs` の `redirects` 設定により、削除済み旧記事（`risk-tolerance-guide` 等10件）は統合後の新記事へ`meta refresh`＋`canonical`＋`noindex`で正しく転送されることを `dist/` のビルド済みHTMLで確認しました。
- **サイトマップ**: `dist/sitemap-index.xml` → `dist/sitemap-0.xml` が生成されており、`robots.txt` からも正しく参照されています（過去の既知の末尾スラッシュ問題は2026-06修正済みとのことで、今回の点検でも新たな不整合は見つかりませんでした）。
- **モバイル対応**: `viewport` メタタグは設定済み、レイアウトは `max-width` とflexboxベースで組まれています。トップページ・ブログ一覧・ニュースレターCTAには画面幅640px/480px向けの `@media` クエリがありますが、ヘッダーやProfileカード等の一部コンポーネントには明示的なメディアクエリがなく、要素数が少ないため大きな崩れは想定しにくいものの、**実機やブラウザの端末シミュレーターでの目視確認までは今回の点検では行えていません**（コード上の確認に留まります）。
- **ローカルの `dist/` は最新ではありません**: 手元の `dist/` は8/11 09:04時点のビルドで、直後の09:29コミット（ふるさと納税記事の更新）を反映していません。GitHub Pagesは`main`へのpushで自動ビルドされる設定のため実害はないはずですが、申請直前に一度最新pushがGitHub Actionsで正常にデプロイ完了しているかだけ、社長かエンジニアに確認いただくと安心です。

## 5. AdSenseポリシー上の注意点（YMYL観点）

### 良い点
- `about.astro` に「特定の金融商品の勧誘や、税務・投資の最終判断を代行するものではありません」という断り書きが既にあります。
- `privacy.astro` にも広告・アフィリエイトの扱いについての説明があります。
- `online-scam-methods-2026.md`（investment詐欺の手口を解説する記事）内で「絶対儲かる」「元本保証」等の断定的フレーズが使われていますが、これは**詐欺の典型パターンとして注意喚起する文脈**での引用であり、問題のある使い方ではありません。

### 要対応（優先度：中）— 記事ごとの免責表現のばらつき
お金関連の記事23本のうち、末尾に「投資にはリスクがある」「最新情報は公式サイトで確認を」といった免責的な一文があるのは10本、**残り13本にはこの種の一文が見当たりませんでした**。しかも古い記事から順に付いていったわけではなく（例: 5月公開の記事にあるが7月公開の記事にない、など）、運用上つけ忘れが発生しているとみられます。
免責文がない記事の例：
- `sbi-vs-rakuten-nisa-2026.md`（証券会社の比較・推奨）
- `car-insurance-review-guide.md`（保険の見直し推奨）
- `furusato-nozei-limit-guide.md`（ふるさと納税＋アフィリエイト広告あり）
- `seikatsu-bouei-shikin-guide.md`（貯蓄額の指南）
- `summer-bonus-2026-allocation.md`（ボーナスの配分指南）
- `credit-card-beginners-guide.md`（クレジットカードの推奨）
- `fixed-cost-defense-guide-2026.md`（保険・通信費の見直し指南）
- ほか

AdSenseの審査基準として免責文の有無が直接の合否ラインになっているわけではありませんが、お金・保険というYMYLジャンルで「断定的な助言に見えないか」を意識する社の方針（`about.astro`にも明記済み）に照らすと、全記事で表現をそろえておいた方が一貫性があり安全です。

### 要対応（優先度：低）— 表現の強さが気になる箇所
`sbi-vs-rakuten-nisa-2026.md` 122行目：
> 「実はSBI証券と楽天証券は**「どちらを選んでも大正解」**と言えるほど…選んだ後に「致命的な損をする」ことはありません。」

投資の損得そのものではなく証券会社選びについての表現ですが、「〜ことはありません」という言い切りがやや強く、免責文もこの記事にはないため、上記の免責追加とあわせて表現を少し和らげておくと安心です。

### 確認できなかったこと
- 実際の検索結果での見え方、Googleによるクロール・インデックス状況、審査担当者の主観的判断は、クロール後でないと分からないため対象外としています。

## 【優先度別まとめ】

| 優先度 | 項目 | 対応 |
|---|---|---|
| 高 | なし | — |
| 中 | 13記事に免責文がない（お金・保険系の実務記事中心） | 各記事末尾に、既存記事（`nisa-beginners-guide.md`等）と同様の免責一文を追記することを提案 |
| 中 | 手元`dist/`が最新pushの1コミット分古い | GitHub Actionsのデプロイが最新まで完了しているかを確認 |
| 低 | `sbi-vs-rakuten-nisa-2026.md`の「致命的な損をすることはありません」がやや断定的 | 表現を和らげる提案（免責追加とセットで） |
| 低 | 一部コンポーネント（ヘッダー等）に明示的なメディアクエリがない | 実機・ブラウザでのモバイル表示の目視確認を推奨（コード上は大きな崩れは想定しにくい） |
